# راهنمای اجرای جمع‌آوری مخازن GitHub

## وضعیت فعلی

در نسخه تحویلی، ابزار انتخاب مخازن و اجرای جمع‌آوری پیاده‌سازی شده است؛ اما نمونه اصلی هنوز جمع‌آوری نشده است. وجود اسکریپت یا فایل پیکربندی به معنی دریافت داده واقعی نیست.

## قبل از اجرا

1. با استاد و اعضای تیم، معیارهای ورود، تاریخ‌های baseline/follow-up، حداقل ستاره و تعداد نهایی را تأیید کنید. تاریخ‌های پیش‌فرض این پروژه `2025-01-01` و `2025-07-01` هستند و نباید پس از مشاهده نتایج تغییر کنند.
2. Python 3.12 و Git را روی ویندوز نصب کنید.
3. فایل رسمی `TestSmellDetector.jar` نسخه 2.2 را از صفحه انتشار رسمی پروژه دریافت کنید و در مسیر `tools/TestSmellDetector.jar` قرار دهید. SHA-256 مورد انتظار در README اصلی ثبت شده است.
4. در صورت داشتن GitHub token، آن را فقط در متغیر محیطی ترمینال تنظیم کنید؛ هرگز آن را در فایل پروژه، Git یا چت قرار ندهید. برای دسترسی عمومی ممکن است بدون token نیز کار کند، ولی محدودیت API شدیدتر است.

## اجرای مرحله‌ای

در PowerShell، از ریشه پوشه پروژه:

```powershell
# ابتدا نمونه آزمایشی ۲۰ مخزن
.\collect_github_sample.ps1 -Count 20
```

پس از بررسی audit و خروجی نمونه آزمایشی، در صورت تأیید تیم:

```powershell
# نمونه اصلی ۱۰۰ مخزن
.\collect_github_sample.ps1 -Count 100 -MaxCandidates 300 -MaxPages 3
```

برای توسعه نمونه به ۲۰۰ یا ۳۰۰ مخزن، ابتدا باید تصمیم تیم/استاد ثبت شود و فایل خروجی تازه ساخته شود:

```powershell
.\collect_github_sample.ps1 -Count 200 -MaxCandidates 600 -MaxPages 6
```

```powershell
.\collect_github_sample.ps1 -Count 300 -MaxCandidates 900 -MaxPages 9
```

توجه: جست‌وجوی GitHub سقف ۱۰۰۰ نتیجه دارد و کامل شدن تعداد انتخاب‌شده تضمین‌شده نیست. اگر audit تعداد کمتر از درخواست را نشان دهد، نمونه را با مخازن ساختگی پُر نکنید.

## خروجی‌هایی که باید حفظ شوند

- `configs/github-sample-N.json`: فهرست مخازن و SHAهای immutable در دو مقطع زمانی.
- `configs/github-sample-N.sampling-audit.json`: معیار جست‌وجو، زمان، تعداد درخواست‌ها، مخازن انتخاب‌شده و دلایل حذف.
- `results/github-sample-N/`: خروجی‌های واقعی استخراج، manifest، وضعیت هر مخزن، فایل‌های CSV، لاگ‌ها و checkpointها.
- `data/repos/`: نسخه‌های cloneشده؛ این پوشه را پاک نکنید تا اجرای مجدد و Resume ممکن باشد.

## چه زمانی می‌توان گفت جمع‌آوری کامل شده؟

فقط وقتی که:

1. `selected` در audit با `requested` برابر باشد؛
2. اجرای pipeline تمام شده باشد؛
3. وضعیت هر مخزن در `repository_status.csv` بررسی شده باشد؛
4. تعداد مخازن موفق، ناقص و ناموفق، تعداد فایل‌های تست، پوشش detector و داده‌های missing گزارش شده باشد.

اگر اجرای pipeline قطع شد، فایل‌های خروجی را پاک نکنید. برای ادامه از همان config و دستور زیر استفاده کنید:

```powershell
.\.venv\Scripts\python.exe -m team7_pipeline run --config configs/github-sample-20.json --resume
```

نام فایل را مطابق نمونه واقعی خود تغییر دهید. اگر run نهایی شده باشد، Resume مجاز نیست؛ اجرای مجدد باید با config و run ID جدید انجام شود.

## محدودیت علمی

این sampler از GitHub Search عمومی و رتبه‌بندی‌شده استفاده می‌کند؛ بنابراین نمونه تصادفی از کل جامعه نرم‌افزارهای Java نیست. نتایج باید همراه با سوگیری‌های انتخاب، محدودیت API، مخازن حذف‌شده، شکست build/detector و توزیع frameworkها گزارش شوند. تعداد مخازن انتخاب‌شده به‌تنهایی معادل تعداد مخازن قابل تحلیل نیست.
